# Decision memo · Sandboxed EPUB inspection

**For Astra 6.2 and Sol 6.2 · 18 November 2026 · Research handoff**

Use a Linux supervisor, one offline Bubblewrap worker per book, W3C EPUBCheck 5.4.0 for conformance, ClamAV 1.4.6 LTS for signature scanning, and a separate static inspector that inventories the entire ZIP. FreshClam is the only runtime component that needs internet access. Give the supervisor sole authority to select files, update scan state, change dispositions and emit JSONL. A worker receives an immutable snapshot and returns bounded evidence. A parser finding must never directly cause a filesystem action.

**Three decisions for Astra before implementation**

1. **Name the freshness clock.** Apply the fixed 72 hours to the publisher's build epoch of the authenticated **daily** release. Verify and load the compatible main and bytecode databases alongside it. Main and bytecode can legitimately be older. Requiring all three build dates to be within 72 hours, or requiring proof of the exact instant the CDN first served a file, would make normal operation infeasible. Record the interpretation explicitly. A publisher outage longer than the window necessarily stops scans. [Talos database format](https://docs.clamav.net/manual/Signatures.html) · [Update process](https://docs.clamav.net/manual/Usage/SignatureManagement.html)
2. **Approve WSL 2 as the Windows runtime and qualify storage separately.** Target Linux filesystems in WSL 2 first. Treat Windows-mounted intake as a separate release test. A successful Linux run says little about Windows open handles, junctions, case folding or durable rename on a mounted Windows volume. Require exclusive/cooperative control of a mutable intake during disposition. Without that assumption, Unix offers no atomic “unlink this pathname only if it still names these bytes” operation. [WSL versions](https://learn.microsoft.com/en-us/windows/wsl/compare-versions) · [WSL file permissions](https://learn.microsoft.com/en-us/windows/wsl/file-permissions) · [Linux rename](https://man7.org/linux/man-pages/man2/rename.2.html)
3. **Require evidence for completed checks.** The security unit is the archive plus its actual members, including unlisted resources. ClamAV explicitly documents a size setting that can skip a file and still treat it as clean. Start with raw archive and individual member scans, byte accounting and a supported-format policy. A worker killed without an attributable book limit is an operational failure. Keep the sandbox, scan coverage and file transactions as independent acceptance gates. [ClamAV scanning](https://docs.clamav.net/manual/Usage/Scanning.html) · [EPUB resource and scripting model](https://www.w3.org/TR/epub-33/)

**Quality heuristics to ship initially.** Use at most two. (1) Count U+FFFD clusters in decoded visible prose, reporting counts, denominator and short contextual spans. A conservative trial threshold is three or more replacements per 1,000 characters over a sufficiently long chapter. Exclude code and quoted Unicode examples. (2) Detect a reversal among at least three explicitly numbered sibling chapters within one part when spine and nav disagree. Require the same language/numbering convention and exclude page lists, prologues, appendix restarts and alternative renditions. Both are review-only. Record rule version, raw counts, relevant headings, positions and rationale. Calibrate on labeled English novels, Chinese vertical text, Japanese ruby, Arabic RTL, bilingual parallel texts, poetry, technical manuals with literal replacement characters, anthologies and fixed-layout comics. Report false positives per language/book type and disable a rule where denominators or structure are unreliable. No dictionary-based “OCR score” or inferred order for unnumbered Chinese chapters.

**Failure attribution.** Record launcher-ready, DB-loaded, member-started and member-completed events on a bounded, validated channel. A generic SIGKILL, host OOM, broken scanner, sandbox setup error, invalid protocol or shared scratch exhaustion stops the batch. For ambiguity, retain the source, run the pinned healthy control independently and stop if attribution remains unclear. Repeated failures of the same stage trip an operational circuit breaker. A failed quality-only run after security passes is operational/undecided unless content evidence proves a defect. A policy trigger already observed can justify quarantine; record everything that did not complete.

## Signatures and scanner classifications

1. Stage a coherent, read-only generation containing official main, daily and bytecode for the chosen engine. Allow only the configured database files plus verified vendor metadata. Reject conflicting CVD/CLD copies, unapproved local signatures and mismatched engine functionality levels. For a simple first deployment, accept complete official CVDs from a persistent FreshClam-managed private mirror. Keep immutable generations and a trusted ingestion manifest of names, SHA-256, database versions, build epochs, engine/FLEVEL and verification results. Distribute the manifest with authenticated provenance if moving between machines. [Talos format](https://docs.clamav.net/manual/Signatures.html) · [Private mirrors](https://docs.clamav.net/appendix/CvdPrivateMirror.html)
2. Verify each database with the pinned vendor verifier, load the exact set successfully and run a known-clean control plus a harmless known-positive control in isolation. Obtain the daily build epoch from verified metadata. Bind it to the authenticated payload/inner database info or a trusted ingestion attestation covering the complete vendor artifact. An outer header read alone is insufficient. For incremental CLDs, require trusted FreshClam processing from a verified base, verified update chain/internal database manifest and the same epoch-to-bytes binding. Until tested, accept full verified CVDs only and configure the mirror accordingly. Include any detached signature/certificate material required by that exact release. Keep trust anchors outside the writable update directory. [Database info](https://docs.clamav.net/manual/Signatures/DatabaseInfo.html) · [CLD definition](https://docs.clamav.net/appendix/Terminology.html) · [sigtool](https://manpages.debian.org/trixie/clamav/sigtool.1.en.html)
3. Compute age using a trusted UTC clock, accepting exactly 259,200 seconds and rejecting future, absent or unparsable epochs, rollback below a persisted trusted generation, or unreliable time. Never substitute mtime, installation time, fetch time, last successful check, DNS TTL or HTTP Date. Offline verification establishes identity, age and loadability relative to that clock; the existence of a newer upstream generation requires an online check.
4. At startup, if stale/missing, lock the updater outside book/output paths, refresh once into a candidate generation, reverify, then atomically publish only a complete generation. On lock contention re-read the winner's generation. Pin it through the batch. If freshness would expire before the next book starts, pause and repeat readiness before dispatch. Keep a valid previous generation on update failure; stale data still fails preflight. Respect FreshClam cooldown, Retry-After, 403/EOL and shared-cloud-IP 429s. Use one persistent updater/cache across jobs or an internal mirror. Never have each transient worker retry downloads. [FreshClam FAQ](https://docs.clamav.net/faq/faq-freshclam.html) · [Supported releases](https://docs.clamav.net/faq/faq-eol.html)
5. For clamscan, 0 means no detection was reported, 1 means a finding, 2 means error. Parse output against the pinned version and expected synthetic object IDs. Promote only an actual malware signature to malware wording. Classify documented limit/encryption alerts, parse failures and unsupported embedded data as incomplete; retain separate heuristic findings. Configure limit alerts and account independently for caps they omit. Missing result, truncated output or unknown diagnostic never becomes clean. Permission, DB load, scanner executable and protocol failures are operational unless the evidence identifies a specific unreadable part of this book. An engine returning fewer results than objects submitted cannot certify the book. Do not use scanner move/remove switches. [Scanner settings](https://docs.clamav.net/manual/Usage/Scanning.html) · [clamscan options and exits](https://manpages.debian.org/trixie/clamav/clamscan.1.en.html)

## File disposition and recovery

Keep a durable operation journal on a qualified local filesystem. SQLite transactions with durable synchronization are a practical machine-readable repair queue and journal (separate tables or databases as configured). Use a stable scan-root identity plus relative path, content SHA-256 and action/policy version for idempotency. Separate root identities prevent collisions when two invocation roots have the same relative names. Validate and escape display paths at the CLI boundary. Preserve original bytes and relative directories at the destination.

1. Acquire a cooperating per-intake lock, lock shared destination/queue operations consistently, open pinned directory FDs and snapshot the opened regular file into private storage. Record device/inode, size, change times and SHA-256. Recheck identity and bytes before committing. A snapshot protects inspection even if a writer holds the original open. If external writers can replace paths concurrently, require an owned handoff directory or exclusive producer agreement for destructive mode. Advisory locks alone do not constrain other writers. On stale identity, emit an operational conflict and preserve the current file. [openat2](https://man7.org/linux/man-pages/man2/openat2.2.html)
2. Commit intent first. For same-filesystem quarantine use atomic no-replace rename under the validated ownership model, then synchronize affected directories. For cross-filesystem quarantine or repair, write a private exclusive temporary file on the destination filesystem from the examined snapshot, verify length and hash, fsync, publish with a filesystem-supported atomic no-replace primitive, and fsync its parent. Fsync newly created directory entries through their parents. Preserve an occupied file even if its basename matches. Journal a deterministic hash suffix and retry no-replace on collision. Only reuse an existing copy after verifying bytes and journal ownership. Plain rename with overwrite and check-then-copy are insufficient. [renameat2](https://man7.org/linux/man-pages/man2/rename.2.html) · [fsync](https://man7.org/linux/man-pages/man2/fsync.2.html)
3. Quarantine removes the validated source only after destination publication is durable; fsync the source parent and mark committed. For repair, keep source, commit queue row only after durable publication. Include root/source, hash, findings, needs_review status and complete copy reference. Queue failure is operational: retain source and published copy, leave pending intent and retry idempotently. Never queue a temp file. A pending intent alone does not count as successful disposition.
4. Recover by verifying actual source and destination hashes against recorded intent. A verified destination plus identical source permits completion under the ownership contract. A changed source, mismatched destination or missing evidence requires intervention; leave available bytes intact. Reconcile a recorded completed rename whose journal commit was interrupted. Journal and clean only own temporary files. Recovery runs after preflight on normal runs; report-only can report pending state without replaying it. A filesystem lacking the required primitives/durability must return an operational error before destructive work. [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html)

## Operator network policy

**Installation route.** Use a trusted Debian 13 Linux base already staged for the target architecture. A provisioning host assembles a signed dependency bundle with the distro Python/JRE/parser/sandbox packages and security dependencies, the pinned upstream EPUBCheck release ZIP and supported ClamAV upstream binary package. Stage binaries, notices, package manifest, SHA-256s and verification keys out of band. A normal worker install uses local files; disable package-manager downloads and unattended services during image assembly. The trixie package pages retrieved here list older EPUBCheck and ClamAV builds. Check the actual security repository against the manifest before substituting a distro engine. Neither Maven nor source checkout is required. For the fallback import the same preassembled OCI image by digest from a local archive with pulls disabled. No registry, auth or layer CDN endpoints are required on either worker path.
