# Malicious EPUBs and defensive coverage
**Decision memo for Astra 6.2 and Sol 6.2 · 18 November 2026**

## Executive recommendation

Keep archive and resource inspection ahead of rendering. Qualify **Foliate (foliate-js on WebKitGTK)** and **KOReader (the CoolReader-derived CREngine)** as the first behavioral pair. Give each reader a fresh profile, its own offline sandbox and the same immutable book. Instrument the reader's request and navigation decisions **and** independently observe the operating-system boundaries for network, files and application dispatch. A network namespace can stop a request without telling the supervisor which book caused it. A reader can also reject a request before a network syscall occurs. Both observations matter.

The strongest direct evidence is an invoice-themed EPUB submitted by two sources on 15 December 2025. Its January 2026 analysis links an archive-path flaw to a remote tracking reference. Either condition is sufficient for v1 quarantine. A renderer might be quiet because it is patched, because the relevant item was skipped or because a later login would be needed for an effect. Conversely, documented Adobe Digital Editions traffic came from the reader itself. Quarantining on all network attempts from a reader process would mishandle that case. [Specimen analysis, 23 Jan 2026](https://security.googlecloudcommunity.com/community-blog-42/a-fake-epub-lecture-6637) · [Xreader advisory, 20 Dec 2023](https://www.zerodayinitiative.com/advisories/ZDI-23-1835/) · [ALA statement, 27 Oct 2014](https://www.ala.org/news/2012/11/ala-welcomes-adobe-action-greater-attention-reader-privacy-concerns)

| Priority | Decision for the project |
|---|---|
| Before either engine opens a book | Keep v1 physical archive reconciliation, read-only snapshots, local resource resolution, signature freshness and per-member security coverage. Sandbox the scanner and converters themselves. Put automatic behavioral testing between v1 security clearance and **both** ordinary release and repair staging. Explicit investigation uses a separately authorized route and cannot reverse quarantine. |
| Before claiming two-engine coverage | Run end-to-end harmless controls for each boundary in each engine and on each target platform. Demand a receipt for the actual rendered target of every required navigation step. If one reader cannot visit a required item, record a review hold. Repeated background noise, missed hooks or silent omissions are qualification failures. |
| Before publishing any repair | Reuse v2's immutable hash and publication transaction. Run the gate on the finished candidate and keep its decision separate from the source's. V3 exact-diff approval and its second persistent-warning approval remain independent. Author text, agent replies, terminal output and monitor strings carry no authority. |
| Readiness | **Architecture recommended; production release unverified.** This checkout has no commits, remote or delivered v1–v4 program. No revision, queue schema, renderer dependency lock or live integration result was available. Reviewed the four behavioral briefs and earlier research handoffs. Windows host observations appear below. |

**Evidence that would change the choice.** Prefer the independently qualified Thorium/Blink fallback if KOReader persistently misses required targets in representative fixed-layout, accessible or media-rich books and the fallback meets the patch/monitor gates. If either direct application adapter cannot expose pre-denial decisions, or the host cannot observe descendants, move that workload to a qualified VM or keep it pending. Collect paired completion rates, reasons for holds, ambiguous-event rates and resource use by book type before setting production limits. **No change to the agreed dispositions is proposed.** Suggested retention duration, monitor architecture and deployment gates below are implementation choices.

## Case and coverage matrix

**Reading the evidence.** A field specimen establishes that malicious bytes existed outside a lab. A documented production privacy behavior establishes that a reader did something. Neither establishes a population infection rate. An advisory or research demonstration establishes a susceptible component and prerequisites. A shared-library case applies to this utility only if its actual binary loads the affected version on a reachable path. “Detected” below means a specific policy condition can be established; it never implies exhaustive detection.

**Prevalence has a denominator only for the historical study.** The 2021 paper reports 7,238 torrent EPUBs and 1,807 files from a second sharing service; the authors found no evidence of tracking or compromise in that analysis. They separately found demonstrable weaknesses in readers and inadequate manuscript vetting in four of six tested publishing services. The later invoice specimen establishes real malicious EPUB content. These observations cannot yield a contemporary prevalence rate, victim count or estimate of scanner sensitivity. Likewise, Check Point's 2021 Kindle research concerned a particular device/ebook processing path fixed in firmware 5.13.5; it is evidence about device attack surface, not attribution of an EPUB incident to these Linux engines. [IEEE study, §§ VI–VII](https://conferences.computer.org/sp/pdfs/sp/2021/893400a247.pdf) · [Check Point research](https://research.checkpoint.com/2021/i-can-take-over-your-kindle/)

**Comparable route.** Snapshot the exact EPUB read-only. From independently checked package metadata construct a bounded itinerary of reading-order IDs, internal TOC targets and reachable footnotes/backlinks. Record rendition, linear/nonlinear items and any unresolved or conflicting targets. Never manufacture a spine from ZIP order. A v1-cleared repair candidate whose required reading order cannot be established enters the gate and can be held. Align viewport, locale, fonts, theme, layout mode, media/autoplay policy, publication scripting, dwell, step caps, fresh cache and accessibility features; record unsupported settings and their effects. Keep trusted UI scripts separate from publication scripting. Configure disabled third-party lookups, sync and updates in workers. Do not neutralize a document resource by rewriting the book before testing. Pin shared image/font/codec dependencies too.

For each action record requested locator, actual committed locator, package member, link origin, whether an internal footnote rendered in a popup or a page, readiness/paint evidence and end-of-step reason. Distinguish a requested jump from a displayed target. Record skipped content, duplicates, lazy assets and bounded dwell. Observe initial import/open and delayed activity until the defined end barrier. A cap reached before a required item was visited leaves coverage incomplete. For structurally deficient inputs, disagreeing locators or a reader silently substituting an error page, report the gap rather than passing that step. UI automation must exercise navigation inside the actual reader; parsing nav XML is only plan construction.

### How to witness denied effects

| Boundary | Enforcement and observation | Attribution limit |
|---|---|---|
| Network and DNS | Private network namespace per engine with no upstream route, external DNS, host sockets or proxy FDs. Log redacted intent at the book resource broker before cancellation. Independently observe descendant connect/send and resolver paths, including local helper IPC. Use a controlled canary listener outside the boundary to demonstrate zero receipt. | Host packet silence misses pre-network denials and DNS failures. A socket event usually lacks the chapter/frame. Identify the initiator and book resource chain or classify ambiguous. A book-local content service, if required, must have a verified process and exact allowed endpoint. |
| Out-of-book reads | Expose one read-only input, minimal immutable runtime/font set and private scratch. Instrument member resolver before it rejects a reference. Correlate kernel file-open intent/result with process, directory FD, working directory, mount namespace, object and requested access. Include broker/helper reads, inherited FDs and direct file access in the qualification inventory. | Boot libraries, fontconfig caches, accessibility and profile reads occur without book-directed host access. A read within an allowed runtime path can still be book-directed; a global path allowlist must not erase that evidence. A pre-open rejection or an object already in memory may generate no file-open event. Record requested/read/bytes-disclosed separately. |
| External launches | Intercept reader dispatch, desktop URI/portal and helper-launch decisions; use a private denying broker or no host bus. Observe process creation/exec across descendants and prevent unapproved execution using the qualified sandbox policy. Private display, no clipboard, host audio, portal, user session or Windows interop. Permit only known reader helpers under constrained roles. | A desktop broker can receive a launch request without spawning a process. A codec/WebKit helper can spawn normally without opening an external app. Record URI scheme class, calling component and navigation context. A book-attributable denied dispatch suffices; never execute the handler to obtain proof. [Freedesktop dispatch](https://portland.freedesktop.org/doc/xdg-open.html) |

**Implementation choice.** Use an out-of-worker supervisor for append-only event collection. On a dedicated Linux runner qualify a process-tree/cgroup-scoped syscall or kernel audit collector (e.g. supervised tracing, or a narrow privileged host collector). Include already-running brokers only if scoped and accounted for. Capture enter/result, stable process identity, sequence numbers, monotonic clock, queue/drop counters and a per-run nonce. Renderer hooks add semantic context; kernel observations provide an independent boundary. Filter volume after preserving required attempts. Seccomp restricts syscall operations but does not interpret arbitrary path strings; Landlock audit visibility depends on kernel ABI and enabled audit. A denied access to a nonexistent pathname can have different evidence from an LSM denial. A single interception technique cannot guarantee all three classes. Pin instruments and probe the actual backend. [Linux seccomp](https://docs.kernel.org/userspace-api/seccomp_filter.html) · [Landlock/audit](https://docs.kernel.org/admin-guide/LSM/landlock.html) · [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)

**Health and attribution.** Before dispatch run a clean reader startup and harmless positive controls for all three classes in each actual adapter; establish that denials and records occur and externally observable effects do not. Use trusted synthetic controls at the correct boundary and a separate inert book-origin control where the engine supports it. If a feature is documented as suppressed, prove where its request is rejected and observed. Confirm helper coverage, sandbox startup, source immutability and profile reset. During runs require start/end barriers, heartbeat, complete event sequences, loss counters and per-engine completion receipts. Reader output is untrusted. Monitor disconnect, event loss, a missing engine or unverified sandbox pauses the batch; untested or affected work stays pending. Previously established quarantine evidence remains actionable and is recorded alongside any incomplete coverage.

For an ambiguous event, perform **one** matched comparison for the affected run, grouping ambiguous events. Use the same engine build, fresh equivalent profile, isolation, settings, instrumentation, timings and navigation actions against a benign control with matched structure. Compare initiator/frame, resource mapping, phase, process and dispatch chain. Evidence of book origin in one run can be enough. Reader-owned provenance and replication in the control support background attribution. An event missing from the control, or matching only by destination/time, is inconclusive. Hold if still uncertain; do not average runs until quiet. If an automatic prohibited action is already attributable in either engine, quarantine takes precedence over a clean run, a crash or an ambiguous second event.

### Deployment and evidence handling

- **Linux.** Start with a patched native Linux kernel, user/mount/network/PID namespaces, delegated cgroup v2 limits and a private virtual display. Retain the renderer's own process sandbox. Bound memory, CPU, PIDs, disk, decoded pixels, output, navigation steps and wall time for the whole process tree. Fresh per-book/per-engine state; pre-staged, signed or digest-pinned updates outside workers. A disposable VM with no NIC/shared folders is the stronger isolation option for explicit quarantined investigations or native codec risk. It still needs guest-level intent monitors. Rootless OCI is an alternative launcher with the same necessary probes; container branding and VM egress denial alone give no attribution.
- **WSL.** Require WSL 2 and record Windows build, WSL/kernel/distro, storage and effective monitoring capabilities. Use an isolated virtual display in the distro. WSLg's host-integrated display, clipboard, audio, host network and interop bridges are inappropriate dependencies for a disposable reader. Keep host drives, interop sockets/executables and shared display services out of the worker. Probe actual denial to a Windows-side canary as well as guest-side canaries. Test Linux filesystem and supported Windows-mounted inputs/outputs separately, including permissions, locks, atomic publish, reboot recovery and trace expiry. [Microsoft WSL comparison](https://learn.microsoft.com/en-us/windows/wsl/compare-versions) · [WSLg integration](https://learn.microsoft.com/en-us/windows/wsl/tutorials/gui-apps) · [Interop](https://learn.microsoft.com/en-us/windows/dev-environment/wsl-interop)
- **Restricted cloud.** Fixture parsing, reducer tests, report redaction, cache-key and simulated failure tests are feasible. A worker lacking user namespaces, a safe display, ptrace/audit privileges, controller delegation or a matching kernel collector cannot certify a live gate. Do not disable inner renderer sandboxing to run nested. Use a qualified separate Linux runner for live integration. Never treat an outer network allowlist or a live Linux test as WSL evidence.
- **Distinct evidence records.** Durable decision contains input/candidate SHA-256, immutable config ID, per-engine status, planned/observed coverage, evidence class, disposition and any separate override. Keep request class, initiator and coarse destination category. Drop URL userinfo, query, fragment, token-bearing path/host labels and raw file paths from normal records. Use keyed local identifiers for correlation where necessary. Never write credentials, book text, tracking tokens or raw terminal controls to stdout. Keep raw traces in a restricted local store per run. Proposed default: retain held/quarantined traces for seven days, configurable; discard quiet-run temporary traces at completion. Store expiry timestamps, clean crash leftovers and test backup/secondary-log handling. Keep audit decisions and reasoned overrides after trace expiry.
- **Cache and publishing.** Identity includes exact book hash, both renderer/frontend versions and build digests, backend/OS and dependency image, effective settings, profile template, fonts/codecs, navigation algorithm/plan/limits, observer/broker configuration, attribution/control policy and decision-policy versions. Changes invalidate reuse. Cache only complete, authenticated, non-operational results under the exact identity; a hold override remains a separate decision bound to the same tuple. Recheck present platform health even on a cache hit and apply v1's current preflight separately. Pin or seal tested bytes through publication, verify the destination hash, and compare-and-swap latest to preserve previous versions under races. Report-only predicts v1 actions with no protected mutations. V2 plan-only generates no candidate, so it has no candidate behavioral result. A quarantined investigation stays quarantined; a candidate hold or quarantine does not alter its parent. Permit a reasoned human override for a **hold alone**. It cannot release quarantine or waive v1–v3 requirements.

## Prioritized gaps and release assessment

1. **Release blockers.** Inspect the delivered v1–v3 commit and real queue/approval/publication entry points. Demonstrate the gate cannot be bypassed on either publication path or intake release. Pin qualified reader/dependency builds, implement trusted adapters and demonstrate loss-aware observation, independent enforcement, per-target receipts and one-comparison attribution. Exercise the full matrix on native Linux and WSL 2. No available evidence supports enabling automatic release today.
2. **Next improvements.** Measure holds by layout, writing system, footnote style, media/accessibility feature and reader; sample background activity after upgrades. Build a benign regression collection, particularly RTL, vertical text, image-heavy and fixed-layout titles. Compare the fallback pair's completion rate. Add more codec/OS combinations only when they improve coverage enough to justify qualification.
3. **Disclose to operators.** A quiet result concerns one byte sequence, two builds, configured features and a finite route. It cannot establish what happens after a login, after a long delay, on a different device/reader, with networking enabled, after clicking an external citation, with personal data already cached, or on every playback/gesture/assistive-technology path. Silent native corruption and agent manipulation can produce no monitored action. No current field denominator establishes prevalence or completeness. Keep the reason for each release, hold or quarantine available independently of trace retention.
