# EPUB repair v2

## Implementation decision

The acceptance contract is the uploaded v2 build brief. The operator requested Linux qualification and deferred WSL. The delivered v1 implementation uses a Python supervisor, an offline Bubblewrap worker, ClamAV, EPUBCheck and SQLite. The memo's description of an empty checkout predates this delivery. The queue already records an operation ID, intake path, SHA-256 and findings.

Use Python’s ZIP reader and a narrow raw-record writer after v1 reconciles the archive inventory. The writer copies untouched local records, including their compressed streams, and replaces only approved XML attribute spans. This avoids the metadata and compression changes of a whole-archive zipfile round trip. The mechanical profile can correct the placement and compression of exactly one otherwise-valid root mimetype. The broader profile additionally admits case-only navigation fixes corroborated by the active manifest and target, and an EPUB 2 package identifier pointer corroborated by the associated NCX. Ambiguous evidence, unsupported layouts or uncertain signature impact require review. Keep publisher text, metadata values and unedited payloads. Inspect the exact derivative with the v1 pipeline before publication.

Use the v1 queue identity and locks, keep distinct accepted objects by hash, and compare retries to both pinned intake and latest accepted findings. The standalone command reads pending v1 entries. Combined mode selects only this scan's eligible books. Both preview paths must stop before candidate creation and publication.

## Defects found in review

The initial combined command emitted two records per eligible book. Initial queue selection omitted entries from a v1 folder override. The first reference rule could retarget a link to an existing chapter even when the manifest separately declared the missing chapter. The first byte-preservation check trusted a digest supplied by the same writer it was checking. Sol revised these paths and the independent tests exercise each case. A final crash-and-replace test found that recovery could publish while reporting an intake hash mismatch. Sol moved pending publication behind intake authentication. The retest observes no new output until the expected bytes are restored. Other revisions restored eligibility after intake damage, checked the current latest object's hash on unchanged runs and strengthened diagnostic identity.

The first full guest repair stopped during candidate inspection. Linux returned `EACCES` when the worker tried to write-open a mode-0400 candidate on its read-only bind mount. The probe expected `EROFS`. Sol kept both the read-only mount check and denied write-open mandatory and accepted the equivalent permission errors. The targeted regression confirms that file mode alone cannot pass the probe on a writable mount.

## Operator checks still needed

WSL 2 was deferred by the operator. Repeat the Linux isolation canary and the repair workflow using the WSL distribution's Python, current ClamAV definitions, EPUBCheck and Bubblewrap. Keep the test library, queue, repair intake and repaired outputs on the distribution's Linux filesystem. Check the expected refusal when configured paths are on a Windows-mounted filesystem such as `/mnt/c`. Automatic repair on that storage is outside the current filesystem policy.

A minimal WSL smoke run can use a disposable configuration with `folder` pointing to the generated `books` directory, separate quarantine and intake directories, and an empty `repaired_output`. Run the following from the checkout.

```sh
python3 -m acceptance.isolation
python3 -c 'from acceptance.v2_fixtures import write_book; write_book("books/mixed.epub", layout=True, case=True, warning=True)'
./epub-triage scan --config smoke.toml --repair --profile broader --report-only mixed.epub
./epub-triage scan --config smoke.toml --repair --profile broader mixed.epub
./epub-triage repair --config smoke.toml --profile broader
```

The preview should list M1 and R1 as unverified with no queue or output created. The combined run should emit one JSONL record, publish one hash-named EPUB, and retain the OCR warning. The rerun should report unchanged and keep the same latest hash. All three CLI invocations should exit 1 because the warning remains. Compare the source, staged copy and output hashes with the report. The retry fingerprint covers the selected profile’s rule revisions and resource limits. A change to a rule in that profile can recheck a partial book even when its remaining defect is unrelated. Physical power cuts, XFS and Btrfs were not exercised in this v2 run. The Linux tests cover process termination, transaction recovery and competing processes.
