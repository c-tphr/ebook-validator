# Decision memo: evidence-based EPUB repair

**Astra 6.2 and Sol 6.2 | 18 November 2026 | v2 research handoff**

## Recommended stack and first release

Reuse v1's offline sandbox, physical member inventory, EPUBCheck, malware scanner, findings and publication primitives. Add a small planner that produces evidence-backed edits, a Python ZIP writer that applies those edits to a private candidate, and an independent verifier that reads the final bytes. Keep the supervisor in charge of the queue and output directory. **No additional setup dependencies or network hosts** are needed if v1 ships its proposed Python/XML stack. Keep calibre out of the production worker.

Ship three rules. The default profile fixes the placement or compression of an otherwise valid `mimetype`. An explicitly selected broader profile adds a case-only correction to a broken navigation link and an EPUB 2 identifier-pointer correction corroborated by the NCX. Record unsupported defects and heuristic warnings on the resulting version. Partial repair is useful when the operator can see exactly what remains.

| Decision for Astra | Recommendation and consequence |
|---|---|
| What counts as preserved? | Require byte-identical uncompressed payloads for every untouched member. For changed XML require byte equality outside approved spans. Allow only declared ZIP layout/compression consequences and verify archive metadata independently. This permits a standard-library writer for a supported ZIP subset. Requiring original compressed streams would favor libzip. |
| Which signed books can pass? | At launch, identify signed targets and refer any proposed edit with proven impact or uncertain coverage for whole-book review. Support an unaffected signed book only when the entire signature scope is understood and unchanged. Start with a narrow local, whole-member reference subset; if the team cannot qualify it, report the limitation and route those books to review. |
| What makes a retry worthwhile? | Rebuild from original intake, reproduce prior successful edits, and require progress against the latest accepted version for a new publication. Treat a byte-identical result as an existing version; a different ZIP encoding alone earns no new version. |
| What v1 was reviewed? | The checkout contains the two briefs, two prompts and the v1 research memo. Git reports an unborn master with no commits; no v1 executable, schema, tests, source revision or configured remote was available. The v1 memo recommends Python, EPUBCheck 5.4.0, ClamAV 1.4.6 and Bubblewrap. These are proposed integration points. Inspect the delivered revision before implementing adapters. |

## Initial rule catalog

Gate all rules on a hash-verified intake snapshot, an eligible v1 disposition and complete current input security coverage. Work only on a reconciled physical inventory. Require a verified defect and an unambiguous old value or structural predicate. Every proposed edit carries its triggering finding, member and locator, exact before/after values, corroborating evidence, scope of allowed changes and an independent postcondition. Check the union of proposed edits against signatures **before** invoking a candidate writer.

| Rule and profile | Supported books and evidence | Minimal change and postcondition |
|---|---|---|
| **M1. Place and store mimetype** · default and broader | EPUB 2.0.1 or EPUB 3 OCF ZIP. Exactly one regular root member named `mimetype`, exactly the 20 ASCII bytes `application/epub+zip`, no BOM/newline, valid CRC, no encryption or extra field. Verify actual first local header and compression method. A message such as PKG-006 conflates missing and misplaced. | Move that member to the first physical position and/or switch it to STORE. Leave remaining members in their original relative order. Verify offset zero, method 0, header name/extra length and exact payload via an independent reader; check central/local agreement and all payload hashes. Skip missing/duplicate/wrong-content/extra-field or unsupported ZIPs. [OCF and mimetype](https://www.w3.org/TR/epub-33/#sec-zip-container-mime) · [EPUB 2 specifications](https://idpf.org/epub/dir/) |
| **R1. Repair path case in a navigation reference** · broader | EPUB 2 NCX `content@src` or EPUB 3 XHTML nav `a@href`. The v1 resolver confirms a missing local resource. Exactly one inventory path matches under ASCII case comparison at the resolved base. The active rendition's manifest independently identifies the correctly cased target and compatible media type. Require an existing unique matching fragment when present; corroborate intended chapter with a second nav/spine or target heading where necessary. | Change only the differing filename letters in that one attribute. Preserve directory traversal syntax within the container, fragment spelling, quoting, encoding and all other bytes. Verify the corrected URL resolves case-sensitively to the evidenced member and intended ID. Skip conflicting paths, rendition/base ambiguity, target disagreement or stale fragment. [EPUB URLs and navigation](https://www.w3.org/TR/epub-33/) · [EPUB 2 NCX](https://idpf.org/epub/20/spec/OPF_2.0.1_draft.htm) |
| **D1. Reconcile a broken unique-identifier pointer** · broader | EPUB 2.0.1 only in the initial catalog. Existing OPF `package@unique-identifier` is dangling (e.g. OPF-030). One `dc:identifier` with an existing unique XML ID differs from the broken pointer only by ASCII case. The correctly associated NCX's single `dtb:uid` exactly equals that identifier's nonempty text. No equally plausible identifier, other rendition conflict, or font/encryption key dependency. | Change only the pointer attribute to the existing ID. Verify exact pointer resolution, agreement with NCX, and identical metadata values, identifiers, roles and ordering. Skip differing UID values, missing evidence, multiple plausible identifiers and valid pointers. This rule never changes the identifier string. [OPF 2.0.1](https://idpf.org/epub/20/spec/OPF_2.0.1_draft.htm) · [EPUBCheck identifier diagnostics](https://w3c.github.io/epubcheck/docs/messages/) |

**Paired fixtures for independent review**

| Apparently similar finding | Repair | Leave unresolved or refer to review |
|---|---|---|
| PKG-006 / packaging | Correct 20-byte member is second and deflated. Place it first and store it. | Member absent, or contains a trailing newline. Constructing or changing content exceeds M1. A duplicate or unsafe ZIP follows v1 security handling. |

A case collision already barred by v1 never reaches the writer. |
| OPF-030 | OPF pointer `BookID`, sole matching ID `bookID`, value `urn:example:edition7`; the linked NCX supplies that exact UID. | NCX supplies another edition ID or both print/electronic identifiers compete. Keep both values. Multiple titles, subtitle, translated/alternate-script title, multiple authors and languages are legitimate; their differences trigger no normalization. |
| Mixed verified and heuristic findings | Fix a qualifying M1 and retain an OCR warning in the accepted-version report. | OCR warning alone, suspected out-of-order chapters, or title inferred from a cover: review only, no writer. |

**URL and byte handling.** Resolve using the book's synthetic container root, effective document base and rendition rules. NCX/OPF/XHTML contexts may differ. Handle the narrow subset whose base is understood; skip unsupported `xml:base`, HTML base, query, encoded delimiters, non-ASCII case folds, external URL, CFI/media fragments or entity-expanded attribute spelling. Match archive names exactly regardless of host filesystem. Keep percent escapes intact when their meaning and edit span are established; otherwise skip. An exact existing target cannot be “improved” by another case match.

Use v1's secure namespace-aware parser to identify the node. A byte-position-aware XML tokenizer can identify its exact quoted attribute value. Verify the byte span maps to that parsed attribute and original member hash. Start with UTF-8, directly spelled values and unambiguous spans; skip unsupported encodings or syntax. Apply disjoint spans in descending offset order; overlapping or stale plans require review. Reparse and independently compare all bytes outside the allowed replacements. Avoid global replacement or whole-document XML serialization. Keep the XML declaration, comments, whitespace, namespace bindings, ID order and text intact. Expat's byte index locates an event; a quote-aware lexical pass still has to find the attribute boundaries. [Expat API](https://docs.python.org/3/library/pyexpat.html)

**ZIP writer contract.** Read the hash-pinned input through the v1 bounded inventory. Stream members under existing aggregate limits. For the launch subset support ordinary unencrypted STORE/DEFLATE entries with encodings, flags, attributes, comments, timestamps and extra fields that the writer can reproduce or explicitly account for. Compare normal entries' names and raw encodings, file types, attributes, timestamps, methods, comments, extras, relative order and uncompressed hashes against input. Preserve the archive comment. Permit recalculated CRC/lengths for edited data, compressed sizes/streams from deterministic recompression, required offsets, and M1's declared changes. Reject other differences. Qualify data descriptors, ZIP64, unknown extras, local/central differences and archive-level signature records individually before allowing such inputs. Never silently strip them. Fix compression level, writer version and zlib build; derive metadata from input, never from the wall clock or OS extraction. EPUB 3 recommends updating publication modification time after changes. For this local repair workflow, preserve publisher metadata and date the derivative in the audit record. An edition-publishing workflow would need a separate date policy. [Python ZIP API](https://docs.python.org/3.13/library/zipfile.html) · [EPUB 3 modification date](https://www.w3.org/TR/epub-33/#sec-opf-dcterms-modified)

## Signatures and acceptance of the exact candidate

**Signature impact.** Inventory `META-INF/signatures.xml`, embedded XML signatures and recognized archive-level or signed-resource formats before planning changes. Absence of the container signature file excludes only container-level XML signatures. For every signature, record its ID, SignedInfo references, referenced manifests and nested references, applicable base/URI, transforms, affected resource or fragment, and intersecting proposed edit. Resolve OCF control-file references under the OCF base rules. Same-document IDs need a unique referent. A local whole-member digest without a transform can be compared directly to member bytes. Physical ZIP reordering alone need not affect a signature over uncompressed member bytes. A signed physical archive is a different case. [W3C OCF signatures](https://www.w3.org/TR/epub-33/#sec-container-metainf-signatures.xml) · [XML Signature 1.1, W3C Recommendation, 11 Apr 2013](https://www.w3.org/TR/xmldsig-core1/)

When an edit changes covered bytes and the digest input demonstrably changes, report the signature, reference and proposed edit and route the **whole book** to review. For unsupported transforms, unresolved nested manifest, nonlocal URI, duplicate ID, unverifiable coverage, unfamiliar signing mechanism or malformed signature, report **impact unknown**, name the evidence and also withhold the entire plan. Do not run arbitrary transforms, retrieve keys/references, strip a signature or re-sign. For the narrow provably unaffected case, require complete reference-graph accounting plus byte equality for signature, referenced objects and relevant context before and after. Keep signer identity/trust separate from preservation. In preview, no candidate exists, so even a disjoint plan is unverified.

**Verification algorithm.** Denote the hash-verified intake by I, the candidate by C and the latest accepted version of the same input lineage by L. L is absent on first repair.

1. Run current v1 security and quality inspection on I, or reuse a demonstrably complete result on the identical hash with the identical verification environment. Resolve every proposed defect to an occurrence in I. A change in input hash skips the entry and continues. A fresh scan may create a new eligible lineage. If input security currently fails, withhold repair and report its v1 reason. Never move the read-only source or intake as part of repair.
2. Plan from I. On retry, include still-applicable earlier accepted edits plus new edits. Before applying anything check individual rule evidence, signature impact, old-value and member-hash preconditions, and disjoint spans. Empty plan or heuristic-only book produces no candidate. `--report-only` stops here at both entry points; emit plan, evidence, uncertainty and `verification=unverified`, with no candidate hash or predicted acceptance.
3. Build C in bounded private sandbox storage. Seal it or reopen an immutable snapshot read-only. Independently check archive inventory, allowed byte deltas and rule postconditions. Run the **entire** v1 pipeline on those exact bytes, including its security coverage, signature scanner, conformance, navigation and quality heuristics. Hold candidate bytes stable through transfer and compare SHA-256 at publication. Any incomplete required check prevents acceptance. An operational verifier failure stops the batch under v1 policy.
4. Compare individual findings as multisets. Normalize to checker/rule namespace and version, code, category/severity, member path, node/attribute identity and typed diagnostic arguments (e.g. target or missing ID). Prefer unique XML ID or a structural anchor plus stable sibling/context evidence. Store raw diagnostic, line/column and matched evidence for display. Map old/new source offsets through the edit spans when needed. For archive findings use the named entry and structural predicate. Raw line, ZIP offset, localized prose or message code alone cannot identify an occurrence.
5. Build one-to-one matches. Keep multiplicity for identical occurrences; require unique attribution of a *targeted* occurrence. A stable unique anchor can survive a line shift. A different target or node yields a new occurrence even under the same code. If two same-code occurrences are indistinguishable and the ambiguity matters to acceptance, decline the candidate. A missing diagnostic after a parser stopped early is a coverage failure. Compare all emitted findings in the v1 policy, including remaining heuristics. Preserve raw validation reports.
6. Accept only when security is complete and clear, quality completed, every claimed edit has its independently checked postcondition, at least one planned verified defect disappeared, and C has no new occurrence relative to I. When L exists, require no new occurrence relative to L either, preserve each recorded prior fix/postcondition, and demonstrate new targeted progress over L for a distinct version. In symbols, require multiset differences `C − I = ∅` and `C − L = ∅` over comparable findings. A change in code count, an XML parse, or an EPUBCheck pass cannot establish identity or intent. An identical C/L hash reuses L with no extra output; an I/C byte match or no targeted progress is a no-op.
7. Freeze validator binaries, policy, dictionaries, locale, parser versions, scanner engine/database generation, limits and finding-identity schema for a comparison. If the tools or signatures change, rescan I, C and available L under the same current stack; retain historical reports and explicitly recheck prior fix predicates. A changed code mapping must be supported by tested equivalence. If L has disappeared, fails its hash check, or prior fixes cannot be compared, leave the latest pointer intact and record the blocker. A signature refresh may require current verification; it need not by itself make every completed repair a new editing job.

A candidate is atomic. For example, M1 can succeed while a navigation edit introduces a defect elsewhere. Discard the entire candidate, report both edit outcomes and failed checks, retain earlier versions and continue to the next book after a book-specific rejection. A dead scanner, unavailable sandbox or output-store failure is operational. Keep candidate rejection distinct from quarantining an original.

## Queue, retries and publishing

**Minimal compatibility layer.** Consume v1 records in their delivered format. Leave existing entries readable by v1. Add a repair sidecar keyed by stable v1 entry ID, or by a canonical tuple of root identity, relative source and intake SHA-256 when no ID exists. Resolve intake locations beneath trusted configured roots without following links. Preserve v1's identity even when two books share bytes. A legacy entry with enough information to locate and authenticate intake can get new current findings via validation; a missing trusted hash or location requires a fresh scan. Never manufacture eligibility from a filename.

| Sidecar record | Minimum durable fields |
|---|---|
| Attempt | Entry/lineage, scan run ID if applicable, I hash, expected L hash/revision, profile, applicable rule IDs and implementation/config digests, writer and verification environment, status/reason, outstanding occurrences, observed input/latest/candidate reports. |
| Edit | Rule/version, member and old member hash, node or ZIP locator, old/new values or structural change, supporting evidence and paired input/candidate occurrence IDs, postcondition result and preserved warnings. Associate every edit with attempt, profile and I/C hashes; shared effects may point to the same report without inventing separate causal proof. |
| Accepted version | Immutable output hash, length/path, input lineage, parent latest hash, attempt ID, edit records, accepted and remaining findings, current latest revision. Keep a unique content object per hash and separate version/attempt relationships. |

**Dispatch.** Standalone repair selects pending and newly retry-eligible partial lineages. Combined scan-and-repair passes only the current scan's eligible entry IDs, including an existing deduplicated queue entry encountered in this scan. Ordinary scans leave repair disabled. In combined preview, hand ephemeral, read-only scan observations directly to the planner using the verified source snapshot; a v1 preview creates no intake copy or queue row. Exclude the repaired-output subtree and aliases from recursive intake discovery. Preserve v1's JSONL, stderr summary and exit-code conventions. In a combined invocation, emit one per-book JSONL result with separate scan and repair fields. Include latest accepted output on a rejected retry, the remaining findings, and an explicit no-publication reason.

**Retries.** Fingerprint the effective profile and versions/configuration of rules relevant to outstanding findings, including newly available applicable rules. Keep the baseline lineage and latest revision in the decision. A broadened profile or relevant rule change reopens a partial repair; equivalent conditions skip repeated work. Failures of infrastructure remain retryable. If an earlier fix can no longer be reproduced from I, record the conflict and preserve L. Version and qualify the writer to make equivalent plans deterministic. A book with the same bytes in two intake paths can share an output object while retaining two distinct audit histories.

**Recoverable publication.** Use v1's journal/store once confirmed. On qualified local storage, SQLite can hold the sidecar, compare-and-swap latest revision and append audit rows in one transaction. The worker never sees this database. Persist an attempt/intent with expected parent; stage completed verified bytes into a private temp on the destination filesystem, check hash and length, fsync the file, publish no-replace to a content-addressed path, and sync the parent and any newly created directories. On an occupied path, independently verify complete bytes before reuse. A wrong-content collision is operational and preserves both existing and prior accepted versions. Then atomically commit the accepted record, edit history and latest pointer against the expected parent. A losing concurrent publisher must reload L and recheck before it can advance latest. Do not choose latest by filename, mtime or transaction completion alone. [SQLite atomic commit](https://www.sqlite.org/atomiccommit.html) · [Linux rename](https://man7.org/linux/man-pages/man2/rename.2.html) · [Directory synchronization](https://man7.org/linux/man-pages/man2/fsync.2.html)

Recovery distinguishes an unverified temp, a complete unreferenced object and an accepted version. Replay a durable verified intent only when object hash, provenance and expected parent still agree. Otherwise preserve existing latest and reconcile or retry. No accepted row may point at an unpublished or partial file. Report-only opens existing state strictly read-only, including the no-database case; no SQLite initialization, journal replay, output mkdir, publication lock file, or queue update. Test WAL side files as part of the protected state. On a mounted Windows volume qualify no-replace, directory durability, case behavior and lock semantics; keep the transactional DB on a qualified filesystem. [WSL filesystem permissions](https://learn.microsoft.com/en-us/windows/wsl/file-permissions)

## Observed evidence and handoff limits

On **Windows, CPython 3.14.10, zlib runtime 1.3.1.zlib-ng, 18 Nov 2026**, an in-memory five-member archive had its valid mimetype at local offset 66, DEFLATE method 8. Rebuilding with fixed entry metadata moved it to offset 0 and STORE method 0. All five uncompressed payloads matched, the CRC check returned no failure, and two rebuilds produced identical bytes (SHA-256 `f5ccbf8078504c03e317d373fa378d04147a0236a888ac931c9f0abae7b01286`). This was a packaging fixture with placeholder package metadata, not a conformant book or a full v1 pass.

On a separate benign XHTML sample, correcting one path letter changed exactly one byte; a default ElementTree parse/serialize of the original failed byte equality. An occurrence-multiset probe correctly identified new node C even as two same-code findings at A and B disappeared. These are focused observations about preservation and comparison; the production writer, lxml and acceptance pipeline were not run.

The WSL discovery call in this session returned access denied. calibre, Java, EPUBCheck and clamscan did not resolve on PATH. No production signing, candidate verification, publication, Linux or WSL acceptance result is claimed. Before Sol binds to v1, Astra should record the delivered commit and inspect a real legacy row, actual finding locations and parameters, scan-run membership, the callable full validator and its coverage signal, and the transaction/no-replace and preview interfaces. If v1 emits only human-readable locations or cannot return an immutable input handle, implement that adapter first. Without those two capabilities the verifier cannot reliably explain which defect disappeared or which bytes it approved.
